# CQA — Conversation Quality Analytics

Локальный MVP для Freedom Broker Hackathon: импорт RU/KZ/EN диалогов, динамический чек-лист, оценка оператора с evidence, версии, апелляции и официальный JSON 1.0.

## Быстрый запуск

Требуется Python 3.11+ и Node.js 22+.

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm install --prefix frontend
npm run build --prefix frontend
# Если .env уже существует, сохраните его: локально там может быть подписанная ссылка.
# Для новой установки: cp .env.example .env
.venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Swagger: http://127.0.0.1:8000/docs.
Запускайте команды из корня проекта. Встроенная раздача UI требует сборки **до запуска** backend.

Разработка (два терминала):

```sh
.venv/bin/uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
npm run dev --prefix frontend
```

Vite: http://127.0.0.1:5173; `/api` проксируется на backend. В production-сборке всё работает с одного origin.

## Архитектура

Модульный монолит: FastAPI + Pydantic + SQLAlchemy, SQLite по умолчанию. React + TypeScript + Vite + Tailwind CSS. Lucide для иконок.

```text
backend/app/
  domain.py       строгие модели, валидация evidence/значений, Decimal-расчёт
  checklist.py    официальная неизменяемая начальная конфигурация
  storage.py      таблицы диалогов, чек-листов, оценок, апелляций, бюджета
  providers.py    единый Provider, Mock и MultiAI (legacy-адаптеры в тестах)
  engine.py       факты → применимость → оценки → проверка → расчёт
  budget.py       устойчивое резервирование бюджета и расчёт стоимости по usage
  exporter.py     отдельные модели и валидатор JSON 1.0
  benchmark.py    выбор 6+6+6, сравнение с ручным эталоном
  cli.py          независимые офлайн-инструменты
  main.py         HTTP endpoints и сохранение результатов
frontend/src/     интерфейс и API-клиент
```

`DATABASE_URL=sqlite:///./data/cqa.db`. Для PostgreSQL задайте URL SQLAlchemy и установите совместимый драйвер. ORM и типы переносимы; полноценные миграции Alembic и конкурентный production-деплой не включены в MVP.

Чек-листы и оценки неизменяемы через API. Изменение чек-листа создаёт новую версию; повторная оценка создаёт новую запись. Решение апелляции создаёт ревизию со ссылкой на исходную оценку. Устаревшую оценку нельзя пересмотреть поверх новой версии того же чек-листа.

## Данные и импорт

В интерфейсе нажмите «Импорт диалогов». Принимаются массив записей, объект `records` или полный ответ организаторов `data.records`. Записи проверяются целиком до сохранения. Повторный импорт неизменённых записей безопасен; изменение существующего транскрипта/набора по тому же ID отклоняется.

Для прямого импорта задайте `ORGANIZER_API_URL` в `.env`, перезапустите backend, выберите DEV/PROD и `group_id`. Ссылка используется только backend и не возвращается браузеру. Не вставляйте её в Git, README или frontend.

Исходный порядок, роли и метки времени сохраняются. Evidence начинается с 1 и включает **все** реплики. Для звонков есть HTML audio player; evidence переводит запись на смещение ISO-метки относительно начала транскрипта. Внешняя запись должна оставаться доступной по URL.

## Оценка и AI через MultiAI

Выберите диалоги, версию чек-листа, MultiAI и модель. Кнопка оценки сначала показывает предварительный расход; реальная генерация требует согласования бюджета, серверного разрешения и отдельного подтверждения в UI. Без разрешения работает Mock, явно отмеченный как технический режим.

Используется единый шлюз `https://multiai.store/v1`, существующий backend-ключ не перезаписывается. Через read-only API проверены модели `gpt-6.1-sol` и `gemini-3.8-flash`; обе есть в каталоге. Согласованный smoke одного RU-чата успешно выполнен на обеих моделях; массовый запуск не разрешён. Двухшаговый pipeline извлекает факты, затем оценивает критерии; evidence проверяется по точным цитатам. Таймауты, ограниченные retry, fallback JSON Schema и отказ при подмене model_id реализованы.

Подробная проверка подключения, env, лимиты, стоимость и безопасный первый запрос: [docs/MULTIAI.md](docs/MULTIAI.md). Кредиты MultiAI не приравниваются к USD; без подтверждённой конверсии генерация блокируется. В настройках доступны проверка соединения без генерации и статистика запросов/usage/резервов.

## Расчёт

AI выбирает значения, Python считает баллы: boolean × вес, числовое / максимум шкалы × вес. Для N/A вес исключается; применимые веса нормализуются до 100. Decimal `ROUND_HALF_UP`, округление итоговой суммы, а не отдельных вкладов. `50.625 → 50.63`. Если применимых весов нет — `null`. Critical никогда не обнуляет итог.

## Конструктор и апелляции

«Чек-листы» → выберите базовую версию → меняйте ID, название, правило, вес, тип, ступени, N/A и его условие → сохраните новую версию. Выберите её в списке диалогов для повторной оценки. Official v1 остаётся неизменяемым и единственным источником официального экспорта.

В карточке нажмите «Оспорить» у критерия и введите комментарий. В «Апелляциях» проверяющий видит весь транскрипт, может подтвердить исходную оценку или выбрать новое значение, rationale/evidence и причину. Сохраняется новая ревизия, балл пересчитывается. Исходная и финальная версии доступны в карточке.

## Официальный JSON 1.0

Кнопки DEV JSON / PROD JSON выполняют проверку, сохраняют файл в `results/dev/results.json` или `results/prod/results.json` и скачивают его. DEV должен содержать 65 ID, PROD — ровно 10 чатов; ID сверяются с импортированным набором. Экспортируются последние оценки **Official v1**. Mock отклоняется; отсутствие оценки/сбой сохраняется честно как `status="error"`, `criteria=[]`, `score=null`, `error`.

Независимая проверка готового файла против исходных данных:

```sh
.venv/bin/python -m backend.app.cli validate-export results/dev/results.json data/dev.json --dataset DEV
.venv/bin/python -m backend.app.cli validate-export results/prod/results.json data/prod.json --dataset PROD
```

Проверяются строгие поля/типы, все 8 criterion_id, диапазоны evidence, совпадение итогового балла и critical_flag, повторы и полнота ID. Проверяйте содержимое rationale на персональные данные до публикации результатов. Commit/push выполняет команда после получения настоящих результатов, приложение их автоматически не публикует.

## Benchmark — этап 3

Заморожены **18 чатов: 6 RU / 6 KZ / 6 EN**, 17 исходных DEV и один явно собственный RU/KZ code-switching. Исходные DEV не менялись. Есть calibration/holdout 9+9, независимые человеческие раунды A/B, разногласия и явный consensus с историей. Без consensus статус `unlabeled`, точность не выдумывается.

Парный отчёт сравнивает одинаковые входы, чек-лист и одну версию pipeline; считает criterion exact-match, языковые срезы, N/A matrices, critical P/R, evidence/цитаты, latency mean/median/p95, retries/validation failures/usage и подтверждённые расходы. final_score не является accuracy. Экспертные записи никогда не включаются в модельные запросы.

```sh
.venv/bin/python -m backend.app.batch_cli prepare
.venv/bin/python -m backend.app.batch_cli preflight --out data/new-preflight-plan.json --limit-usd 0.50
.venv/bin/python -m backend.app.batch_cli report
```

Эти команды не делают платных вызовов. Уже подготовлен `data/stage3-preflight-final.json`: **6 оценок на 3 чатах × 2 модели**, ожидается 12 HTTP-запросов, верхний предел 24 с retry. Консервативный резерв **23.084 ₽ ≈ $0.28104**; запуск ожидает нового разрешения на число оценок и бюджет. `ALLOW_PAID_CALLS=false` сохранён.

Подробный формат ручной разметки, импорт/экспорт шаблонов, ограничения и команды будущего batch для 10 настоящих PROD: [docs/STAGE3_BENCHMARK.md](docs/STAGE3_BENCHMARK.md). Старые одиночные экспертные записи — черновики, автоматически в Ground Truth не превращаются. PROD сейчас не запускался, фиктивный JSON не создан.

## Проверки

```sh
.venv/bin/python -m pytest backend/tests -q
npm test --prefix frontend
npm run build --prefix frontend
```

Покрыты расчёт, N/A, точные типы, evidence, JSON, импорт, новые критерии, повторная оценка, апелляции/история, контроль бюджета, retry и метрики. Полный API smoke выполняется на временной SQLite; платных запросов нет.

Браузерный smoke: импорт локального DEMO → mock-оценка → карточка → evidence → апелляция → решение → новая версия → настройка чек-листа. Этот сценарий демонстрирует функциональность, а не точность AI.

## Ограничения MVP

Нет авторизации: запускайте только на loopback/в доверенном окружении. Нет фоновой очереди, отмены задания и распознавания аудио/интонации. Внешние адаптеры проверены с подменой HTTP; реальная генерация обеих MultiAI-моделей проверена на одном RU-чате; качество на полном DEV не измерено. Точность не заявляется. Нет корпоративной базы тарифов/регламентов для независимой проверки финансовых ответов. Данные SQLite хранятся локально без шифрования; для production нужны доступ, миграции, журнал пользователей и политика хранения.
